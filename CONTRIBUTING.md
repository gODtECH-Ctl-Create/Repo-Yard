# Contributing to Repo Yard

Welcome to Repo Yard. This repository is both a learning project and a real collaborative project, so contributions should follow the same workflow we teach.

## Before you start

1. Read the repository README and the lesson you are working on.
2. Check the open issues for existing work.
3. Choose an issue labeled `status: ready`.
4. Comment `/claim` on the issue before starting substantial work.

RepoOps will mark the issue as `status: in-progress` when the claim is accepted.

## Contribution workflow

```text
Find ready issue
      ↓
/claim
      ↓
Create focused branch
      ↓
Make the change
      ↓
Commit
      ↓
Push
      ↓
Open Pull Request
      ↓
Review
      ↓
Fix requested changes
      ↓
Merge
```

## Branch naming

Prefer clear names such as:

- `feat/lesson-branches`
- `fix/conflict-example`
- `docs/improve-pr-guide`
- `chore/update-mission`

## Pull Requests

Use the repository Pull Request template. Keep Pull Requests focused and explain:

- what changed
- why it changed
- how it was tested
- which issue it addresses

For issue-linked work, use GitHub's closing syntax where appropriate, for example:

`Closes #12`

## Working on an issue you can no longer complete

Comment `/unclaim` so another contributor can pick it up.

Do not hold an issue indefinitely.

Repo Yard currently limits non-maintainer contributors to two active RepoOps-managed assignments at a time.

## Documentation quality

Repo Yard is designed for beginners, so technical accuracy and clarity matter equally.

When adding a lesson:

- explain the idea before the command
- show the command
- explain what the learner should expect
- include a small practice task
- avoid assuming prior Git knowledge
- check commands and links before opening the Pull Request

## Pull Request review

Reviewers should focus on:

- correctness
- beginner-friendly explanations
- accurate Git and GitHub behavior
- working examples
- scope
- broken links or instructions
- accidental secrets or credentials

Be specific and respectful when requesting changes.

## Questions and proposals

Use GitHub Issues for problems, improvements, and learning-content proposals. Search existing issues before opening a duplicate.

Thanks for helping make Repo Yard a better place to learn and contribute.
