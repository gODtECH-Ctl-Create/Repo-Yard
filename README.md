# 🏗️ Repo Yard

> **Learn Git and GitHub by actually using Git and GitHub.**

Repo Yard is a hands-on learning ground for developers who want to go from:

**"I don't know what `git push` means."**

to:

**"Give me the repository. I know how to work on it, collaborate, review changes, resolve conflicts, and ship."**

## 🗺️ The Yard Journey

```text
🌱 START → 💻 WORK LOCALLY → 🌿 BRANCH → ✍️ CHANGE → 📦 COMMIT
→ ☁️ PUSH → 🔀 PULL REQUEST → 👀 REVIEW → 🔧 FIX → ⚔️ CONFLICTS
→ 🤝 COLLABORATE → 🏗️ ADVANCED → 🚀 CONTRIBUTOR READY
```

## 🎯 What you will learn

| Level | You will learn |
| --- | --- |
| 🌱 Beginner | Git, GitHub, repositories, clone, status, add, commit |
| 🌿 Builder | branches, push, pull, remotes, tracking branches |
| 🔀 Contributor | Pull Requests, issues, reviews, updates, forks |
| ⚔️ Problem Solver | merge conflicts, revert, reset, stash, recovery |
| 🏗️ Advanced | repository scaffolding, templates, GitHub Actions, branch protection, release workflows |
| 🚀 Team Ready | open-source workflow, collaboration, repository maintenance and automation |

## 💻 The core workflow

```text
GitHub
  ↓ clone / fork
Your Computer
  ↓ edit
git status → git diff → git add → git commit
  ↓ git push
GitHub
  ↓ Pull Request
Review → Fix → Merge
```

## 🤝 Repo Yard is itself a classroom

Contributors use **RepoOps** to manage work:

```text
ready issue → /claim → work → Pull Request → review → merge
```

So collaboration is taught by practicing collaboration.

See [CONTRIBUTING.md](CONTRIBUTING.md).

## ⚠️ Beginner rule

Do not memorize Git commands first.

Understand **where you are, what changed, where the change lives, and where you want it to go**. Then choose the command.
